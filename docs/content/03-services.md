# サービスの構造化 — 実績はサービスの中に置く

> **2026-10-16 更新。** 事業内容（`/services`）の構成を作り直したので、§1・§4〜§8 を書き直した。

> **4つの事業（IaaS / SaaS / BPaaS / TaaS）**に置き換わった。最新の構造は [07-structure.md](07-structure.md) が正。
> §2（ページの型）と §3（実績の構造）は考え方としてそのまま生きている。

## 1. 4つの事業（2026-10-16 改訂）

事業内容は、客の種類ではなく「お客様に何が届くか（価値）」と「それを支える手段」で並べる。4つの形をとる。

「〇〇 as a Service」は「〇〇を月額などで、使う分だけ提供する」という意味。

| 形 | 一行で言うと | 手段（図のタイル） | お客様に届く価値（図の上の段） | 中身の例（詳細ページにだけ書く） |
|---|---|---|---|---|
| **IaaS**（Infrastructure as a Service） | サーバーなどの土台を、持たずに借りる | マネージドクラウド | いまの運用費を下げる | いま動いているホームページ（例: WordPress）や業務システムを中身はそのまま引き取り、自社クラウドで運用する「HP 運用代行」。旧案の「ホームページ移転・保守」「マネージドプライベートクラウド」はここ |
| **SaaS**（Software as a Service） | ソフトを、買わずに月額で使う | ソフトウェア | 作らずに、仕組みが手に入る | 顧客管理（phox）、集客の分析（ティルカヨ）、LINE ツールなど。本来なら開発が要るものを月額で |
| **BPaaS**（Business Process as a Service） | 業務そのものを、ソフトと人のひと組で引き受けてもらう | コンサルティング（ソフトウェアの上に乗る） | 業務ごと任せる | MEO 代行、SEO 代行・サイト改善、販促（DM・フォーム営業）。ソフト＋担当者で集客の業務を最初から最後まで回す。旧案の「MEO」「SEO」はここ |
| **TaaS**（Talent as a Service） | 技術者に、自社チームの一員として入ってもらう | スペシャリスト | 腕の立つ人を、チームに迎える | 0UTL1ER の技術者がお客様のチームに入って働く。旧案の「エンジニア派遣・育成」の言い換え。**「派遣」とは書かない**（労働者派遣事業の許可が要る業態だと受け取られる） |

4つの関係（`/services` の図の形そのもの）:
- **マネージドクラウドは土台。** IaaS だけでなく、SaaS と BPaaS もこのクラウドの上で動く。だから図では左端を縦に伸び、下で SaaS・BPaaS の下まで広がる
- **BPaaS ＝ ソフトウェア＋コンサルティング。** ソフトだけ渡すのが SaaS、そこに担当者が付いて業務ごと回すのが BPaaS。だから図ではソフトウェアの上にコンサルティングが乗る
- **TaaS だけ性質が違う。** ほかの3つは「事業を預かる」、TaaS は「人を出す」。土台にも乗らない。会社の中心ではなく資金繰りのための事業なので、図では右端に離して置く
- 旧案の「受託開発」はどれか1つに対応しない。作って渡すのではなく、できた仕組みを月額で使ってもらう（SaaS）か、技術者がチームに入る（TaaS）かで提供する

決まり:
- **事業 = 1ページ**（`/services/iaas` など4ページ）。メニューやプラン（HP 運用代行、phox、MEO のライト／スタンダード…）はページ内で見せる。製品・メニューごとにページは作らない
- `/services` の図には、事業の形の名前（IaaS…）を上の段にだけ、タイルには手段の名前だけを出す。**製品名・メニュー名は図に出さない**
- 1つの事業が店舗にも企業にも当てはまるのが普通。ページは1つにして、入口（トップ・ブログ）から両方リンクする

### 提供状況の棚卸し（要確認）

旧案の候補を4つの事業に振り直した。**提供状況と、詳細ページにどこまで書くかを決めてほしい。**

| 旧案の候補 | 入る事業 | 実態（把握している範囲） | 詳細ページに載せるか |
|---|---|---|---|
| MEO 代行 | BPaaS | 主力事業 | |
| SEO 代行・サイト改善 | BPaaS | 主力事業 | |
| 販促（DM・フォーム営業など） | BPaaS | 試行中 | |
| ホームページ移転・保守（HP 運用代行） | IaaS | 既存客への追加提案として実施（例: サイトを自社基盤へ移して SSL・速度を改善） | |
| マネージドプライベートクラウド | IaaS | 自社基盤 kuki-dc は稼働中。外部への提供実績は？ | |
| 自社ソフト（phox、ティルカヨ、LINE ツール） | SaaS | phox は社内で稼働。外部提供の形は？ ティルカヨは構想中 | 準備中のものをどう扱うか |
| 受託開発 | SaaS または TaaS | ？ | 単独では載せない方向 |
| エンジニア派遣・育成 → スペシャリスト | TaaS | ？ | 「派遣」と書かない |

## 2. 詳細ページの共通の型

4つの詳細ページ（`/services/{iaas|saas|bpaas|taas}`）を同じ順番で作る。訪問者が迷わないことと、書く側が抜けに気づけることが目的。

**実装（2026-10-16）:** 冒頭（写真＋見出し＋リード文）の下に、Payload のコレクション「サービス」（URL名 ＝ `iaas` などのスラッグ）の段を出す。段は「こんなお悩みに / やること / 実績 / 選ばれる理由 / 料金 / 進め方 / よくある質問」の7つで、**中身が書いてある段だけ表示される**（空の段は見出しごと出ない）。下の表の 9・10（関連する記事・専用の問い合わせ）は Payload の段に無いので、付けるかは未決（07 §7-10）。

| 順 | セクション | 答えること | 必要なデータ |
|---|---|---|---|
| 1 | **冒頭** | 誰の、何を、どうするサービスか（1〜2文） | 対象、解決すること、主な成果の数字1つ |
| 2 | **こんなお悩みに** | 自分ごとか | 実際に聞いた悩みを3〜5個（客の言葉のまま） |
| 3 | **やること** | 具体的に何をしてくれるか | 作業の一覧。「月に何回」「何を」まで書く |
| 4 | **実績** | 本当に結果が出ているか | 数字の実績（§3-A）＋事例カード2〜4件（§3-B） |
| 5 | **選ばれる理由** | 他社と何が違うか | 理由3つ。各理由に根拠を1つずつ（事実・数字・仕組み） |
| 6 | **料金** | いくらかかるか | プラン表、初期費用、最低契約期間、解約条件、含まれない作業 |
| 7 | **進め方** | 頼んだらどうなるか | 相談→診断・提案→契約→開始→報告の流れと、各段階の期間 |
| 8 | **よくある質問** | 残った不安 | 5〜10問。実際に受けた質問から |
| 9 | **関連する記事** | もっと知りたい | 対応するブログカテゴリの記事を3本 |
| 10 | **問い合わせ** | 次に何をするか | このサービス専用の入口（例:「無料でマップ診断」）。フォームはサービス名を自動で入れる |

- 実績を「やること」の直後に置くのは、料金を見る前に「結果が出ている」と分かってもらうため
- 実績が少ないサービスは、数字の実績を省いて事例カード1件でもよい。**0件なら「実績」セクションごと外す**（「準備中」と書くと逆効果）

## 3. 実績の構造

### 実績は4種類
| 種類 | 中身 | 置く場所 | 例 |
|---|---|---|---|
| **A. 数字の実績** | サービス全体の集計 | サービスページ §4 の頭、トップページ | 「支援店舗 42店」「平均継続 18か月」「稼働率 99.9%（過去12か月）」 |
| **B. 事例** | 1社ごとの話（課題→やったこと→結果） | サービスページに事例カード、詳細は個別ページ | 「久喜市の美容室: 3か月でルート検索 2.4倍」 |
| **C. お客様の声** | 客の一言 | 事例の中、サービスページ | 写真・名前・業種つきの短いコメント |
| **D. 取引先** | 社名・ロゴの一覧 | 会社情報、サービスページの下部 | 掲載許可を得たものだけ |

### 事例のデータ項目
1件の事例は「主に属するサービス」を1つ持つ。複数のサービスにまたがる場合は、関連サービスとして他のページにも出す。

```yaml
slug: kuki-hair-salon-meo
service: bpaas                   # 主に属する事業（URL の親になる。iaas / saas / bpaas / taas）
related_services: [iaas]         # ほかの事業の詳細ページにも出す場合
title: 久喜市の美容室、3か月で Google マップからの予約電話が2倍に
client:
  display: 久喜市の美容室 A店    # 公開の程度に合わせた表記
  disclosure: anonymous          # named（社名・ロゴ可） / anonymous（業種・地域のみ） / private（数字のみ）
  industry: 美容室
  area: 埼玉県久喜市
  size: スタッフ5名
period: 2026-04 〜 2026-07      # 支援期間
challenge: |                     # 依頼前の状態と困りごと（数字があれば数字で）
actions: |                       # やったこと（作業の一覧）
results:                         # 結果。必ず「何を・いつからいつまで・どこで測ったか」をつける
  - label: 電話の件数
    before: 月18件
    after: 月37件
    source: Googleビジネスプロフィールの分析（2026年4月と7月の比較）
voice: |                         # お客様の声（任意・許可済みのもの）
cover: ./cover.jpg
permission:                      # 掲載許可の記録（社内用・非表示）
  granted_by: 店長 〇〇様
  date: 2026-08-01
  scope: 業種・地域・数字の掲載可、店名不可
published_at: 2026-08-10
```

### 実績を載せるときの決まり
- **掲載許可を書面かメールで残す。** 許可の範囲（社名可・業種のみ・数字のみ）も記録する
- **数字には測り方を添える**（期間・出典・比較の基準）。「最大〇倍」は一番良い例だけを切り取った表示として景品表示法上の問題になりうる
- **順位の保証や「必ず」は書かない**
- 季節要因や他の施策の影響があり得るときは、その旨を一言入れる
- 古い実績（目安2年以上）は更新するか外す

## 4. URL

```
/services                               … 事業内容（4つの事業を1枚の図で。客の種類での振り分けはしない）
/services/{iaas|saas|bpaas|taas}        … 事業の詳細ページ
/services/{事業}/cases/{slug}           … 事例の詳細（※下記）
/cases                                  … 全事例の一覧（メニューに出さない。営業で URL を送る用）
```

例:
```
/services/bpaas
/services/bpaas/cases/kuki-hair-salon-meo
/services/iaas
```

- 事例は主に属する事業の下に置く。関連する事業のページからはカードでリンクするだけ（同じ事例を2つの URL に置かない）
- **要確認:** 事業が6サービスから4つに変わったので、「MEO の事例が `/services/bpaas/cases/…`」で違和感がないか。無理があれば `/cases/{slug}` に一本化して、詳細ページの「実績」の段からカードでリンクする（07 §7-8）
- 旧案の `/services/meo` `/seo` `/website` `/development` `/private-cloud` `/dispatch` は作らない（公開前の案なので転送も不要）

## 5. 事業ごとに書くべき中身

§2 の型を、4つの事業で何を埋めればよいかに落としたもの。**太字が、第三者から見て特に無いと困るもの。** 旧案の6サービス分の中身を、入る事業ごとにまとめ直した。本文は代表が Payload「サービス」（id 2〜5）に書く。

### IaaS — マネージドクラウド（いまの運用費を下げる）
- こんなお悩みに: サーバー代・保守費が高い、制作会社との契約が切れて誰も面倒を見ていない、表示が遅い、SSL が切れた
- やること: **いま動いているサイト・システムを中身はそのまま引き取る手順（例: WordPress のイメージをそのまま移す）、移すと何が良くなるか（SSL・速度・障害時の対応）、どこまで代わりに運用するか**（監視・バックアップ・更新）。メニュー名「HP 運用代行」はここで初めて出す
- 実績の数字: **稼働年数、稼働率、運用しているサイト・サービスの数**、移転で下がった月額の例、表示速度の改善
- 料金: **月額、初期費用（移転作業）、ドメイン・サーバー代の扱い、同等構成の AWS やレンタルサーバーとの比較**
- 信用に関わる情報: **データの所在（国内・どこ）、バックアップの方法と頻度、監視の体制と時間帯、障害時の連絡方法、解約時のデータ返却**
- よくある質問: ドメインは誰の名義か、解約したらサイトとデータはどうなるか、今の制作会社が別でも頼めるか
- 注意: 実際の体制と違うこと（「24時間365日監視」など）を書かない

### SaaS — ソフトウェア（作らずに、仕組みが手に入る）
- こんなお悩みに: 顧客管理が表計算のまま、集客の数字がバラバラで見られない、ツールを作る予算も人もいない
- やること: **提供するソフトの一覧と、それぞれ何ができるか**（phox＝顧客管理、ティルカヨ＝集客の分析、LINE ツール…）。製品名はここで初めて出す。導入までの流れ、データの持ち込み・持ち出し
- 実績: 使っている会社・店の数、自社で使って出た数字（自社プロダクトも実績として出せる）
- 料金: **月額、初期費用、最低契約期間、解約の申し出期限、含まれないこと（設定代行など）**
- よくある質問: 自社に合わせた変更はできるか、解約したらデータはどうなるか、スマホで使えるか
- 注意: 準備中のもの（ティルカヨなど）を「提供中」と読める書き方にしない

### BPaaS — コンサルティング（業務ごと任せる）
- こんなお悩みに: 担当者がいない、何をすればいいか分からない、ツールを入れたが使いこなせていない
- やること: **ソフト（SaaS）＋担当者で、集客の業務をどう回すか。** MEO（Googleビジネスプロフィールの初期整備、投稿の頻度、写真の追加、口コミ返信の代行範囲、キーワード設計、競合調査、月次レポート）、SEO・サイト改善（診断で何を見るか、改善の範囲、記事作成の有無、報告）、販促（DM・フォーム営業）。**MEO と SEO はこの段の中で分けて書く**（ページは分けない）
- 実績の数字: 支援店舗数、業種の内訳、平均継続期間、表示回数・電話・ルート検索の変化、検索からの流入・順位の変化（期間と語句を明示）
- 料金: **月額、初期費用、最低契約期間、解約の申し出期限。** 単発の診断と月額の区別
- よくある質問: 口コミを増やせるか（やらせ口コミはしないことの明示）、効果が出るまでの期間、オーナー権限は誰が持つか、解約後どうなるか、今のサイトのままでできるか

### TaaS — スペシャリスト（腕の立つ人を、チームに迎える）
- こんなお悩みに: 社内に技術が分かる人がいない、採用しても定着しない、一時的に手が足りない
- やること: **どんな技術者が、どういう形でチームに入るか**（領域: インフラ・クラウド、開発、データ分析など。週何日、常駐かリモートか、期間）。契約の形（準委任など）。受け入れまでの流れ
- 実績: 入った先の業種、期間、やったこと（許可を得たもの）
- 料金: 目安の幅（月額〇〇万円〜）、**何が含まれて何が含まれないか**
- よくある質問: 小さな会社でも頼めるか、途中で人を替えられるか、成果物の権利
- 注意: **「派遣」と書かない。** 「チームの一員として働く」「チームに迎える」と言う。労働者派遣事業の許可番号や情報公開の項目は要らない（派遣ではないため）。契約の形が実態と合っているかは別途確認

## 6. メニューとトップページへの反映

### グローバルナビ
```
サービス▾ / ブログ / 会社情報 / [お問い合わせ]
```
「実績・事例」を外して4項目にする。

### 「サービス」のプルダウン
**旧案の「店舗向け / 企業向け」の2列はやめる**（事業内容を客の種類で分けなくなったため）。載せるのは4つの事業。並べ方（1列か2列×2か、価値の一言を添えるか）は未決（07 §7-9）。文言は `/services` の図と同じ言葉を使い、ここで新しく作らない。

```
マネージドクラウド（IaaS） / ソフトウェア（SaaS） / コンサルティング（BPaaS） / スペシャリスト（TaaS）
─────────────────────────────────────────
事業内容を見る →
```

### トップページ（01 §5 からの変更）
| 順 | セクション | 変更点 |
|---|---|---|
| 2 | 事業内容 | 客の種類のカードではなく、4つの事業の図の縮小版か「価値と手段」の一覧（07 §7-11）。製品名・料金は出さない |
| 3 | 数字で見る実績 | 各事業の「数字の実績」から代表的なものを3〜4個集める |
| 4 | 事例 | 各事業の事例から代表的なものを2〜3件。カードから詳細ページの事例へ飛ぶ |
| 8 | ブログ新着 | 02 のとおり |

### ブログとの関係（02 からの変更）
- ブログの「事例」型は、事例の**裏話・詳しい解説**として書き、必ず詳細ページの事例にリンクする。事例の本体は詳細ページ側に置く
- ブログのカテゴリと事業の対応（案。07 §7-12 で要確認）:

| ブログのカテゴリ | 事業 |
|---|---|
| 集客・MEO | BPaaS |
| Web・SEO | BPaaS、IaaS（HP の移転・保守） |
| 開発 | SaaS、TaaS |
| インフラ・クラウド | IaaS |

## 7. 原稿の置き場所

- **本文の正本は Payload（payload.0utl1er.tech）のコレクション「サービス」。** 4つ分の下書きがある（id 2〜5、状態「準備中」、URL名 ＝ `iaas` `saas` `bpaas` `taas`）。段ごとに書けたところから表示される
- 図の値（価値・手段・写真）はコード（`src/lib/services.ts`）に固定で書いてあり、Payload では変えない
- 写真の出典は `public/images/services/CREDITS.md`（いずれも Unsplash、商用利用可・表記不要。自社撮影の写真があれば差し替える）
- `docs/content/services/_template.md` は §2 の型を埋めるための空の原稿。Payload に書く前の下書きに使ってよい
- 事例（§3 のデータ項目）はサイトに組み込む段階で Payload のコレクションにする

## 8. 決めてほしいこと

1. **§1 の棚卸し表**: 各事業の提供状況（提供中 / 準備中 / 載せない）と、準備中のもの（ティルカヨなど）を詳細ページにどう書くか
2. **4つの詳細ページの本文**: Payload「サービス」（id 2〜5）の7つの段を、書けるところから
3. **実績を出せる顧客**: 掲載許可をお願いできそうな顧客が事業ごとに何件あるか
4. **料金を載せるか**: 金額を出す / 「〇〇円〜」の目安だけ / 載せない（載せない場合は理由と相談の流れを丁寧に）。事業ごとに違ってよい
5. **事例の置き場所**: `/services/{事業}/cases/{事例}` のままか、`/cases/{事例}` に一本化するか（§4）
6. **TaaS の契約の形**: 「派遣」と書かないことは決まり。実際の契約（準委任など）が実態と合っているかの確認
