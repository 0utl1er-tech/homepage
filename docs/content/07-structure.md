|---|---|---|
| 1 | 客は2種類（店舗・地域ビジネス / 企業のIT担当）。トップとブログの入口はこの2つで分ける。**ただし事業内容（`/services`）は客の種類ではなく、4つの事業で並べる**（§5、変更の記録 2026-10-16） | 話が通じる言葉がまったく違う。一方で、事業内容は「何が届くか」で見せた方が会社の全体像が伝わる |

| 6 | **スローガン「Beyond the Correlation」は2か所だけ** | 繰り返すとくどい（旧HPの反省） |
| 7 | 同じ文を複数のページに書かない | 旧HPは同じ説明文が4回出ていた |
| 8 | 中身は Payload（payload.0utl1er.tech）で管理する | 06 の調査。顧客サイトも同じ仕組みで提供する |

| 11 | **読む人は、入口から奥へ進むほど変わる。** トップと事業内容（図）は、企業の担当者などリテラシーのある人が「この会社は何をしているか」を把握するためのもの。事業の詳細ページは、そのサービスを実際に使う人に向けたもので、LP（1枚もののセールスページ）に近づけてよい | 1つの文体・1つの深さで全部を書くと、どちらの読者にも刺さらない。入口は会社の全体像を短く、奥は使う人の言葉で具体的に（2026-10-16 決定） |

### 事業の4つの形（言葉の意味）

「〇〇 as a Service」は「〇〇を月額などで、使う分だけ提供する」という意味。お客様に説明するときは次の一行で言う。

| 形 | 一行で言うと | 0UTL1ER での手段 | お客様に届く価値 |
|---|---|---|---|
| IaaS（Infrastructure as a Service） | サーバーなどの土台を、持たずに借りる | マネージドクラウド | いまの運用費を下げる |
| SaaS（Software as a Service） | ソフトを、買わずに月額で使う | ソフトウェア | 作らずに、仕組みが手に入る |
| BPaaS（Business Process as a Service） | 業務そのものを、ソフトと人のひと組で引き受けてもらう | ソフトウェア＋コンサルタント | 業務ごと任せる |
| TaaS（Talent as a Service） | 0UTL1ER の人材に、自社チームの一員として入ってもらう | スペシャリスト | 腕の立つ人を、チームに迎える |

TaaS だけ性質が違う。ほかの3つは「事業を預かる」、TaaS は「人を出す」。**「派遣」という言葉は使わない**（労働者派遣事業の許可が要る業態だと受け取られる）。「チームの一員として働く」「チームに迎える」と言う。

### 読む人の層（入口から奥へ）

| 階層 | 主に読む人 | 書き方 |
|---|---|---|
| トップ / 事業内容（図） | 企業の担当者・経営者など、ITやマーケティングの話が通じる人。会社の全体像を知りたい | 短く、構造で見せる。IaaS / SaaS / BPaaS / TaaS のような区分の言葉を使ってよい。製品名・価格・手順は出さない |
| 事業の詳細ページ（`/services/{事業}`） | そのサービスを実際に使う人（店主、現場の担当者、情シス）。自分の困りごとが解決するかを知りたい | LP に近づけてよい。お悩み → やること → 実績 → 料金 → 進め方 → FAQ → 相談、の順で、使う人の言葉で具体的に。区分の言葉（SaaS など）は説明なしで使わない |
| 事例・ブログ | 詳細ページまで来た人の裏付け、または検索から直接来る人 | 数字と測り方。ジャンルに合わせた末尾の案内で詳細ページへ戻す |

**決まり**: 上の層にあるページに、下の層の中身（価格・手順・製品名）を持ち込まない。下の層のページで、上の層の抽象的な言葉だけで終わらせない。

### スローガンの使いどころ

| 使う | 使わない |
|---|---|
| トップのファーストビューに小さく1回（英語のまま） | フッター、ローディング画面、各ページの見出し、本文、説明文（meta description）、メンバー紹介 |
| 会社情報の「社名の由来」の中で1回（ここだけ意味を説明してよい） | お問い合わせ、サービスページ、ブログ |

検索結果や SNS 共有時に出るタイトル・画像（トップページのもの）には社名と並べて置いてよい。サイトの中で繰り返さないことが目的。

## 4. トップページ ＝ 各ページのダイジェスト

**決まり**
- トップの各段は、どれか1つのページ（または一覧）の要約。対応先のない段は作らない
- 各段の最後に「詳しく →」で対応ページへ
- 中身は対応ページと同じデータ（Payload）から出す。トップ用に別の文章を書かない
- 説明は短く。詳しい説明は対応ページで

| 順 | 段 | 対応するページ | 出すもの | データ（Payload） |
|---|---|---|---|---|
| 1 | ファーストビュー | ― | 社名、何の会社かを普通の日本語で1文（例:「埼玉・久喜で、お店の集客と企業のシステムを支えています」）、スローガン（英語・小さく1回）、入口ボタン2つ | 会社情報 `oneLiner` |
| 2 | 事業内容 | `/services` | 4つの事業の図の縮小版か、4つの事業の「価値」と「手段」の一覧（製品名・料金は出さない）。「事業内容を見る →」 | `src/lib/services.ts` の4つの事業（価値・手段）。本文は Payload「サービス」 |
| 3 | 実績 | 各サービスの事例 / `/cases` | 数字の実績 3〜4個（時点つき）と、事例カード 2〜3件 | サービス `metrics`、事例（`featured`） |
| 4 | 会社 | `/company` | 代表の写真と短いメッセージ、所在地、「会社情報を見る →」 | 会社情報 `message`、メンバー |
| 5 | ブログ | `/blog` | 新着を店舗向け・企業向けに分けて 2〜3本ずつ | ブログ記事 |
| 6 | お知らせ | `/news` | 最新3件（日付と題名だけ） | お知らせ |
| 7 | お問い合わせ | `/contact` | 電話番号・受付時間・フォームへのボタン | 会社情報 `phone` `hours` |

旧案（05）にあった「選ばれる理由」「進め方」はトップから外す。どちらもサービスごとに中身が違うので、各サービスページで書く。

## 5. 各ページの中身

### 事業内容（`/services`）— 1枚の図

ページ全体が1枚の図。**上の段がお客様に届く価値、その下に手段が階段のように積み上がる。** 列は左から IaaS / SaaS / BPaaS / TaaS。

```
 IaaS                 SaaS                    BPaaS              TaaS
 いまの運用費を下げる   作らずに、仕組みが手に入る  業務ごと任せる       腕の立つ人を、チームに迎える
┌────────────┬──────────────┬──────────────┐ ┌──────────────┐
│            │               │コンサルティング│ │              │
│            ├──────────────┴──────────────┤ │              │
│マネージド   │        ソフトウェア            │ │スペシャリスト  │
│クラウド     ├─────────────────────────────┤ │              │
│            │   （マネージドクラウドが土台）    │ │              │
└────────────┴─────────────────────────────┘ └──────────────┘
```

| 列 | 上の段（価値） | 下の段（手段のタイル） | タイルの形 | 意味 |
|---|---|---|---|---|
| IaaS | いまの運用費を下げる | マネージドクラウド | 左端を縦に伸び、下では SaaS・BPaaS の下まで広がる階段 | いま動いているホームページや業務システム（例: WordPress のサイト）を中身はそのまま引き取り、自社のクラウドで運用して維持費を下げる。クラウドは SaaS・BPaaS の土台でもある |
| SaaS | 作らずに、仕組みが手に入る | ソフトウェア | SaaS の列では一番上まで届き、BPaaS の列ではコンサルティングの下に入る階段 | 顧客管理や集客の分析など、本来なら開発が要る仕組みを、作らずに月額で使える |
| BPaaS | 業務ごと任せる | コンサルティング（ソフトウェアの上に乗る） | BPaaS の列の一番上 | ソフトと担当者がひと組になり、お客様の集客の業務を最初から最後まで動かす |
| TaaS | 腕の立つ人を、チームに迎える | スペシャリスト | 土台（クラウド）に乗らない縦長の柱。右端に離して置く | 0UTL1ER の技術者がお客様のチームの一員として働く。ほかの3つが「事業を預かる」のに対し、これは「人を出す」。会社の中心ではなく資金繰りのための事業なので右端 |

決まり:
- 事業の形の名前（IaaS など）は上の段にだけ出す。タイルには手段の名前だけ
- 図には製品名（phox、ティルカヨ、LINE ツールなど）も個別メニュー名（HP 運用代行など）も出さない。詳細ページに書く
- 「派遣」と書かない（§1）
- 各タイルは写真。出典は `public/images/services/CREDITS.md`（いずれも Unsplash、商用利用可・表記不要。自社撮影の写真があれば差し替える）
- 図の下に4行の短い注釈（IaaS ＝ いま動いているものを引き取り、運用費を下げる ／ SaaS ＝ 作らずに、できあがった仕組みを使う ／ BPaaS ＝ ソフトと人で業務ごと引き受ける ／ TaaS ＝ 0UTL1ER の技術者がお客様のチームに入る）
- 図の値（価値・手段・写真）は `src/lib/services.ts` に固定で書いてある。Payload で変える対象ではない

### 詳細ページ（`/services/iaas` `/saas` `/bpaas` `/taas`）— 4つとも同じ型

1. **冒頭**: 写真（図と同じもの）＋ 見出し（手段の名前）＋ リード文
2. **本文**: Payload のコレクション「サービス」（URL名 ＝ `iaas` などのスラッグ）から出す。段は次の順で、**中身が書いてある段だけ表示する**（空の段は見出しごと出ない。「準備中」とは書かない）

| 順 | 段 | 中身 |
|---|---|---|
| 1 | こんなお悩みに | 客の言葉のまま 3〜5個 |
| 2 | やること | 作業の一覧（「月に何回」「何を」まで）。ここで初めて製品名・メニュー名を出す（例: IaaS → HP 運用代行、SaaS → phox） |
| 3 | 実績 | 数字の実績＋事例カード 2〜4件（0件なら段ごと外す） |
| 4 | 選ばれる理由 | 理由3つ、それぞれに根拠 |
| 5 | 料金 | プラン、初期費用、最低契約期間、解約条件、含まれない作業 |
| 6 | 進め方 | 段階と期間 |
| 7 | よくある質問 | 実際に受けた質問 5〜10問 |

- Payload には4つ分の下書きがすでにある（id 2〜5、状態「準備中」）。**本文は代表が書く。** Payload に本文が無い間は `src/lib/services.ts` の冒頭文だけが出る
- 旧案の「関連する記事」「このサービス専用のお問い合わせ」は Payload の段には無い。付けるなら仕組みの追加が要る（§7-10）

### 事例（`/services/{事業}/cases/{事例}`、一覧 `/cases`）
- 事例は「主に属する事業」の下に置く。MEO・SEO の事例は `/services/bpaas/cases/…`、HP の移転・保守の事例は `/services/iaas/cases/…` になる想定。**事業が4つに変わったので、この置き方で無理がないかは要確認**（§7-8）。詳細ページの「実績」の段に出す事例を Payload でどう結びつけるかも未決
- 見出しに結果の数字 → 「課題 / やったこと / 結果」の要約 → 業種・地域・期間 → 本文 → お客様の声 → 同じサービスの相談ボタン
- 掲載許可が「許可済み」でないと公開できない（Payload で強制済み）
- 数字には測り方と期間。順位保証・「No.1」・最大値の切り取りは書かない

### ブログ（`/blog`、`/blog/category/{ジャンル}`、`/blog/{記事}`）
- `/blog`: 入口2つ（お店の集客の話 / 開発・インフラの話）→ ジャンルのタブ → 新着一覧
- ジャンル別: 説明 2〜3行 → まず読む3本 → 一覧 → 対応サービスへの案内
- 記事: 書き手（写真・肩書・メンバーページへのリンク）、公開日・更新日、目次、本文、関連記事、末尾の案内（ジャンルに合わせる）
- 比較・選び方記事は冒頭に開示文（Payload で必須項目化済み）
- ジャンル: 集客・MEO / Web・SEO / 開発 / インフラ・クラウド / 会社・考え方
- Zenn・note には書き直した版だけ。全文転載しない

### 会社情報（`/company`）
| 段 | 中身 |
|---|---|
| 会社概要 | 商号、設立、資本金、代表者、所在地、電話、従業員数、事業内容、許認可・登録番号、取引銀行、主要取引先、法人番号 |
| 代表メッセージ | なぜこの会社をやっているか |
| **社名の由来** | **スローガンの意味を説明するのはここだけ**（相関の線から外れた点＝OUTLIER。散布図の絵もここ） |
| 沿革 | 年と出来事 |
| メンバー | 写真・担当 → `/members/{メンバー}` |
| アクセス | 地図、道順、駐車場 |

### メンバー（`/members/{メンバー}`）
写真、肩書、経歴、専門領域、外部リンク、**書いた記事の一覧**（Payload の「書いた記事」をそのまま出す）。書き手のページを兼ねる。

### お知らせ（`/news`）
日付・題名・本文のみ。休業・料金改定・メンテナンスなど。

### お問い合わせ（`/contact`）
- 相談したいサービス（選択式。サービスページから来たら自動で選ばれる）/ 会社名・店名 / お名前 / メール / 電話（任意）/ 内容
- 送信後: 受付メールの自動返信、「2営業日以内に連絡」
- 電話番号と受付時間をフォームの横に
- **送信先の仕組みは未決**（今は画面が変わるだけで、どこにも届いていない）。§7
